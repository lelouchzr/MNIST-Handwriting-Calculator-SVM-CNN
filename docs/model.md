# Model card

## Scope and provenance

InkCalc recognizes isolated handwritten digits and basic arithmetic symbols in a
single horizontal line. It does not implement general mathematical OCR, fractions,
superscripts, equations, touching glyphs, or multi-line expressions.

The original implementation, architecture, synthetic pen paths and frontend are
written for InkCalc. The inspiration is
[Youjia Zhang's calculator](https://github.com/YoujiaZhang/MNIST-Calculator-Handwriting-recognition).
No upstream code, dataset archive, illustrations or model weights are included.

Digits use [MNIST](https://yann.lecun.com/exdb/mnist/), distributed through the
[Keras dataset mirror](https://storage.googleapis.com/tensorflow/tf-keras-datasets/mnist.npz).
Credit: Yann LeCun, Corinna Cortes and Christopher J. C. Burges. The downloaded
archive is cached outside Git, with its SHA-256 recorded in `models/metrics.json`.
Operator images are generated by `scripts/train.py` from original drawing routines.

## Pipeline

1. Group strokes whose horizontal bounds overlap or are within seven logical pixels.
2. Rasterize each group to a light-on-dark grayscale image.
3. Crop, fit within 20 × 20, center by mass on a 28 × 28 frame.
4. Extract 324 HOG features (9 orientations, 7 × 7 cells, 2 × 2 blocks).
5. Predict with a linear SVM and three-fold sigmoid probability calibration.

An isolated mark smaller than twelve logical pixels is treated as a decimal point.
The canvas uses 1,000 logical pixels across, preserving aspect ratio on phones.

## Recorded evaluation

Seed: 42. The committed model uses 20,000 randomly selected MNIST training digits
and 3,900 generated operators (650 per class). Test digits are the first 2,000
samples of the separate MNIST test split; they are not used for training or calibration.

| Evaluation set | Samples | Accuracy |
| --- | ---: | ---: |
| MNIST test digits, all 16 classes eligible | 2,000 | 95.65% |
| Fresh generated operators, all classes eligible | 600 | 99.33% |

These results are generated by the training script, not end-to-end expression
accuracy. Synthetic operator evaluation uses the same drawing family as training,
so it overestimates performance on human handwriting. No real handwritten-operator
benchmark or segmentation benchmark is provided. Probability scores are estimates
under the training distribution; high scores can still be wrong.

## Reproduce

```sh
uv sync --locked
uv run python scripts/train.py --digits 20000
uv run pytest
```

Retraining downloads MNIST on the first run (about 11 MB), writes the model and
metrics, and needs network access. The committed artifact allows normal app startup
without any download. Only load the trusted model from this repository: joblib/pickle
artifacts can execute code and must never be accepted as uploads.

## Recognition inspection and occlusion sensitivity

`POST /api/recognize` includes the original prediction, all 16 class probabilities,
the raster crop and a PNG preview of its normalized 28 × 28 input. Manual edits
affect the expression label only. Small marks use the existing geometric decimal
rule; they explicitly expose no classifier probabilities or model explanation.

`POST /api/explain` accepts the bounded stroke request plus a zero-based
`symbol_index`. It segments the submitted drawing again and explains that symbol's
original top-scoring class. No client-supplied label selects the explanation target.

The normalized floating-point image stays fixed. Each 5 × 5 window is set to zero,
HOG is recomputed without recropping or recentering, and the calibrated classifier
predicts all 576 perturbed samples in one batch. For class c, each window's change is
`p(c | original) - p(c | masked)`. The displayed value at a pixel is the average of
the changes for all overlapping windows that contain it, including border windows.
The sign is preserved. A zero-effect map stays zero without normalization errors.

The UI scales color magnitude per symbol, labels values in percentage points, and
uses both color and hatching to distinguish the sign. This is a local perturbation
sensitivity measure, not a causal attribution or a guarantee of model correctness.
Masking can create inputs outside the training distribution. Display PNGs quantize
the input to eight bits; inference and masking retain the normalized float values.
The HOG feature refactor preserves the original recognition/training transform;
the committed model does not need retraining.

## Known limitations

- Leave space between symbols. Overlapping x-ranges can merge unrelated symbols.
- Narrow digits, parentheses and division marks can be ambiguous. Inspect the
  predictions or type the corrected expression before calculation.
- Only mouse/stylus stroke input is supported; photographs are not accepted.
- Calculations use decimal arithmetic, a maximum of 256 input characters, a bounded
  syntax tree, and a result magnitude limit of 10¹⁵. Display rounds to 12 decimals.
- History stores at most 20 results in this browser. Drawings are not persisted.
- In the documented local setup, handwriting is sent only to the local Python API.
  Hosting the API elsewhere changes where handwriting is processed.
